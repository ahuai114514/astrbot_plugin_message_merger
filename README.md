# astrbot_plugin_message_merger

该项目由 Codex 编写。

这是一个 AstrBot 消息合并插件，采用“零等待取消”策略：第一条消息立即进入原有 LLM 流程，不增加静默等待；如果同一用户在旧请求完成前继续发消息，插件会取消旧的 AstrBot pipeline task，并让最新事件携带已经合并的消息重新生成。

## 行为

- 按 `统一消息来源 + 群聊范围 + 用户 ID` 隔离缓存，不会合并群里不同用户的消息。
- 无法取得可靠用户 ID 时不执行合并，避免串消息。
- 指令前缀（默认 `/`、`!`）以及引用、图片、文件、语音、视频、转发等非纯文本消息不参与合并。
- 已经被其他插件处理、已经发送结果或已经停止传播的事件不会进入缓存。
- 不自行调用模型，继续使用 AstrBot 当前会话的模型、人格、上下文和工具。
- 缓存通过 pipeline task 的完成回调清理，不依赖 `after_message_sent`，可兼容会终止发送后事件传播的插件。
- pipeline task 在普通消息捕获阶段立即绑定；即使 LLM 关闭或流水线提前退出，缓存也会随 task 完成而清理。
- 普通消息捕获器使用最低优先级，让指令和其他业务插件先处理。
- 高优先级处理器只记录消息到达序号；即使不同事件经过其他插件的耗时不同，合并时仍按原到达顺序排列。
- 加入新消息会超过条数或字符限制时，插件会开启新批次并保留上一批请求，不会丢弃已经取消过的用户消息。

## 重要边界

插件只能取消仍在运行的旧请求。如果旧回复已经发到平台，平台通常无法可靠撤回；此时后续消息会作为新的请求处理。取消前已经消耗的 token 无法退回。

如果旧请求已经开始执行工具，或已经进入流式发送，插件不会取消该请求，也不会把它并入新一轮，以避免工具副作用或截断已经开始发送的回复。这种情况下两条消息仍可能分别回复。

该实现依赖 AstrBot 4.25.x 的 pipeline 调度与取消传播行为，因此最低兼容版本为 AstrBot 4.25。

## 配置

- `enabled`：总开关。
- `max_messages`：一次最多缓存的消息条数，默认 8；设为 `0` 时不限制条数。
- `max_chars`：合并历史消息的字符预算，默认 4000；设为 `0` 时不限制。当前最新消息不会被截断。
- `ignore_prefixes`：不参与合并的指令前缀，默认 `/` 和 `!`。

`ignore_prefixes` 中的空字符串会被忽略。批次达到 `max_messages` 或 `max_chars` 限制时可能分别产生多次回复，这是避免丢失用户消息的保护行为。

## 安装

将本目录复制到 AstrBot 的插件目录并在管理面板加载，按需调整配置后重载插件。
